# ID Selector — Express + Vue

Тестовое приложение для работы с 1 000 000 ID без создания миллионного массива в памяти.

## Что реализовано

- исходный диапазон ID `1..1_000_000`;
- левый список содержит все невыбранные элементы;
- правый список содержит выбранные элементы в сохранённом сервером порядке;
- фильтр по ID в обоих списках;
- infinity scroll, API никогда не отдаёт больше 20 строк за запрос;
- ручное добавление нового уникального положительного ID;
- Drag&Drop сортировка выбранных, включая сортировку отфильтрованного/частично загруженного списка;
- выбранные ID и их порядок живут в памяти Express-процесса и переживают refresh страницы;
- поисковые строки намеренно не сохраняются;
- серверная очередь с дедупликацией одинаковых pending-операций;
- добавление новых элементов обрабатывается батчем раз в 10 секунд;
- чтение, выбор, удаление из выбранных и reorder — батчем раз в секунду;
- защита от повторного добавления ID на уровне структуры данных (`Set`) и очереди;
- unit-тесты для store и dedup queue.

## Почему миллион элементов не хранится массивом

Начальный набор детерминирован: это диапазон `1..1_000_000`. Backend генерирует только нужные 20 элементов текущей страницы и пропускает выбранные. В памяти хранятся только:

- дополнительные вручную созданные ID;
- `Set` выбранных ID;
- массив порядка выбранных ID;
- текущие операции очередей.

Так потребление памяти зависит от фактически изменённого состояния, а не от размера базового диапазона.

## Семантика Drag&Drop при фильтре

Frontend отправляет порядок только тех выбранных элементов, которые сейчас загружены и участвуют в DnD. Backend находит их позиции в глобальном `selectedOrder` и заменяет значения только в этих позициях. Поэтому элементы, скрытые фильтром или ещё не подгруженные infinity scroll, не «прыгают» и не теряют относительное положение.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Открыть:

```text
http://localhost:5173
```

Vite проксирует `/api` на Express (`http://localhost:3001`).

## Production-like запуск

```bash
npm install
npm run build
npm start
```

После сборки Express раздаёт `client/dist` сам. Открыть:

```text
http://localhost:3001
```

## API

- `GET /api/state`
- `GET /api/items/available?search=&cursor=&limit=20`
- `GET /api/items/selected?search=&cursor=&limit=20`
- `POST /api/items` `{ "id": 1500000 }`
- `POST /api/selection/:id`
- `DELETE /api/selection/:id`
- `PUT /api/selection/order` `{ "ids": [30, 10, 20] }`

`limit` принудительно ограничивается значением 20 на backend, даже если клиент передаст больше.

## Очередь и дедупликация

`BatchQueue` хранит pending-операции в `Map<dedupKey, Promise>`. Если до flush приходит операция с тем же ключом, второй вызов получает Promise уже поставленной операции, а сама операция исполняется один раз.

Ключи строятся по смыслу операции:

- `add:1500000`;
- `select:42`;
- `unselect:42`;
- `reorder:30,10,20`;
- параметры read-запроса.

Даже если одинаковые операции попадут в разные батчи, состояние остаётся идемпотентным: `Set` не допускает повторного выбора/создания одного ID.

## Ограничения по условию задачи

Хранилище намеренно in-memory. После перезапуска Express-процесса выбранные элементы, сортировка и вручную добавленные ID сбрасываются. Для тестового это соответствует требованию «без БД, достаточно хранения в памяти на время жизни приложения».

## Бесплатный деплой на Render

Проект можно разместить одним Web Service без Docker: Express в production сам раздаёт собранный Vue frontend.

1. Загрузить репозиторий в GitHub/GitLab/Bitbucket.
2. В Render выбрать **New → Web Service** и подключить репозиторий.
3. Выбрать **Node** и **Free** instance.
4. Build Command: `npm install && npm run build`
5. Start Command: `npm start`
6. Health Check Path: `/health`

Переменную `PORT` задавать вручную не нужно: Render предоставляет её процессу, а сервер уже использует `process.env.PORT`.

Также в корне лежит `render.yaml` с теми же настройками для Render Blueprint.

Важно: бесплатный Web Service может быть остановлен хостингом при бездействии/перезапуске. Так как по условию тестового состояние хранится только в памяти процесса, при перезапуске оно сбрасывается.
